MSA Projects

Portal pessoal para organização, apresentação e evolução dos meus projetos.

O MSA Projects é um portal pessoal criado para reunir, organizar e apresentar projetos, experimentos, ideias e experiências de desenvolvimento em um único ambiente.

🎯 Objetivo

Criar um ambiente centralizado para organizar, desenvolver e apresentar meus projetos de forma clara, organizada, expansível e de fácil manutenção.

A estrutura foi pensada para permitir diferentes tipos e categorias de projetos, sem limitar o sistema a uma quantidade fixa de classificações.

  • Projetos Colaborativos
  • Projetos Educacionais
  • Projetos de Brincadeira
  • Projetos da Comunidade
  • Projetos dos Colaboradores
  • Projetos do Fundador
  • Projetos Acadêmicos
  • Projetos de Entretenimento
  • Projetos Experimentais

As categorias não são definitivas e podem surgir conforme novos projetos, experiências e necessidades forem aparecendo.

🔄 Uma nova versão

Esta versão nasceu de uma decisão importante: em vez de continuar adicionando funcionalidades à estrutura antiga, o projeto será reconstruído do zero com uma arquitetura mais organizada.

O MSA Projects original serviu como experiência prática inicial. A nova versão utiliza essas experiências para melhorar a organização dos dados, separar responsabilidades, facilitar a inclusão de novos projetos, criar componentes reutilizáveis e preparar o projeto para crescer.

🧠 Aprendizado de arquitetura

Um dos principais objetivos desta versão é aplicar, na prática, conhecimentos estudados em Arquitetura de Sistemas, especialmente a ideia de separação de responsabilidades presente no padrão MVC (Model–View–Controller).

O projeto não utiliza um framework MVC tradicional. Em vez disso, os princípios do MVC são utilizados como referência arquitetural para organizar o frontend.

M — Model

Representado principalmente pelos arquivos JSON, que armazenam os dados dos projetos sem exigir que essas informações sejam registradas diretamente no HTML.

V — View

Representada principalmente por HTML e CSS. O HTML define a estrutura e o CSS define a aparência, sem precisar conhecer a origem dos dados.

C — Controller

Realizado principalmente pelo JavaScript, que atua como intermediário entre os dados e a interface, realizando carregamento, tratamento e preparação das informações.

Princípio central

Quem apresenta os dados não precisa saber de onde eles vieram.

Isso facilita futuras mudanças na origem dos dados sem obrigatoriamente exigir uma reconstrução da interface.

🏗 Arquitetura e organização

A arquitetura do MSA Projects está sendo construída de forma modular, separando dados, lógica e interface.

Dados → JSON → JavaScript → HTML → CSS → Interface

O CSS também é dividido por responsabilidade: base para fundamentos, components para componentes reutilizáveis e páginas para características específicas de cada tela.

Regra principal: componentes definem como um componente deve aparecer; páginas definem como esses componentes são organizados dentro de uma página.

🧩 Componentes reutilizáveis

A nova estrutura se preocupa com reutilização para evitar que cada página recrie os mesmos elementos.

  • Header
  • Menu de navegação superior
  • Botões
  • Cards de projetos
  • Modais
  • Footer

🗃️ Dados

O projeto utiliza JSON para armazenar informações estruturadas. A intenção é evitar cadastrar os dados diretamente no HTML sempre que essas informações puderem ser tratadas como dados.

{
  "nome": "Exemplo",
  "categoria": "Projeto de Brincadeira",
  "descricao": "Descrição do projeto"
}

A interface utiliza essas informações para construir os elementos necessários.

🗄️ Banco de dados

Conforme definido no README desta versão, atualmente não será utilizado banco de dados. A proposta desta etapa é trabalhar com arquivos JSON como fonte de dados.

Isso também faz parte do aprendizado arquitetural do projeto. No futuro, caso exista necessidade real de utilizar banco de dados, API, backend ou sistema administrativo, a arquitetura poderá ser adaptada.

A utilização de JSON nesta versão não significa que a arquitetura precisa permanecer limitada a JSON.

📚 Documentação

A documentação técnica é construída junto com o projeto e registra não apenas como o código funciona, mas também por que determinadas decisões foram tomadas.

Entre os assuntos documentados estão CSS, JavaScript, JSON, arquitetura, organização do projeto, padrões e decisões de desenvolvimento.

Cada etapa pode gerar ajustes nas anteriores. Isso faz parte do processo de desenvolvimento.

🔎 Diferenças em relação ao projeto anterior

  • Estrutura mais simples → arquitetura mais organizada
  • Dados mais próximos da interface → dados separados em JSON
  • Maior dependência entre arquivos → separação de responsabilidades
  • Menor reutilização → componentes reutilizáveis
  • Crescimento mais manual → estrutura preparada para expansão
  • CSS mais concentrado → CSS dividido por responsabilidade
  • Menor documentação → documentação durante o desenvolvimento

A intenção não é considerar a versão anterior como um erro. Ela foi uma etapa importante para entender quais problemas surgiriam conforme o projeto crescesse.

🎓 Projeto como experiência de aprendizado

O MSA Projects também funciona como um projeto prático de aprendizado, aplicando conhecimentos relacionados a arquitetura de sistemas, organização de projetos, separação de responsabilidades, MVC, manipulação de JSON, JavaScript, HTML, CSS, componentização, documentação, manutenção e escalabilidade.

Dessa forma, o projeto não serve apenas para apresentar projetos. Ele também registra a evolução do conhecimento aplicado na prática.
